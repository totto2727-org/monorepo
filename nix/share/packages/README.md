# Local Nix packages

This catalog serves users who select local packages and maintainers who update their build definitions.
Run the commands below from the repository root.

## Build and run oo-cli

```bash
nix build ./nix/share/packages#oo-cli
./result/bin/oo --version
nix run ./nix/share/packages#oo-cli -- --help
```

The package builds [oo-cli v1.9.8](https://github.com/oomol-lab/oo-cli/tree/v1.9.8) from source with [`bun2nix.mkDerivation`](https://github.com/nix-community/bun2nix/blob/2.1.2/docs/src/building-packages/mkDerivation.md).
The builder fetches locked dependencies, installs them offline, compiles the executable with Bun, and installs `bin/oo`.
Bun, Node.js, and npm downloads are not required at runtime.
The package generates the upstream Open Flow references before compilation and includes them with the bundled skills.

The catalog supports `aarch64-darwin`, `aarch64-linux`, and `x86_64-linux`.
It exposes `packages.<system>.oo-cli` and `overlays.default`, which adds `pkgs.oo-cli`.
The catalog defaults to the same FlakeHub nixpkgs channel as the root development flake.
The two macOS consumers set `inputs.nixpkgs.follows = "nixpkgs"` on `local-packages` to reuse their host input, including for bun2nix and its Bun compiler.
The sandbox retains the catalog's separate input because its stable nixpkgs provides Bun 1.3.3, whose compiled upstream ESM executable fails the runtime checks.
The bun2nix URL has no release tag; `flake.lock` records the exact revision.
The existing `pass-cli` package remains available through the same interfaces.
The catalog also exposes `packages.<system>.bun2nix` for dependency-file generation.

The personal macOS configuration uses the compiled package through its existing connection-settings wrapper.
The sandbox configuration installs the compiled package directly.
These changes take effect after the corresponding Home Manager or system configuration is rebuilt.
They do not activate a configuration automatically.

## Validate oo-cli locally

```bash
nix flake check ./nix/share/packages
nix build ./nix/share/packages#oo-cli --no-link
vp run --filter @app/nix check
```

The package's install checks run with an isolated home directory and telemetry disabled.
They check the version, help output, bundled-skill metadata, and generated Open Flow reference.
The CLI checks use an empty `PATH` to detect an external runtime dependency.
`nix flake check` validates the catalog outputs; `nix build` builds oo-cli and runs its install checks for the current system.
No dedicated GitHub Actions workflow is required.

## Update oo-cli

1. Select an upstream release that satisfies the repository's release-age policy.
2. Update `version`, `rev`, the source hash, and build metadata in `oo-cli.nix`.
   Use the source commit's Unix timestamp in milliseconds for `BUILD_TIMESTAMP`.
3. Regenerate `oo-cli-bun.nix` from that release's unmodified `bun.lock`:

   ```bash
   source=$(nix build ./nix/share/packages#oo-cli.src --no-link --print-out-paths)
   nix run ./nix/share/packages#bun2nix -- \
     --lock-file "$source/bun.lock" \
     --output-file nix/share/packages/oo-cli-bun.nix
   vp run --filter @app/nix fix
   ```

4. Run the local validation commands above.
5. Update the release link in this document.

`oo-cli-bun.nix` is generated by the pinned bun2nix version, not maintained by hand.
Each dependency has its own integrity hash from the upstream lockfile.
The package disables lifecycle scripts and runs only the upstream reference-generation script before compilation.
Use Nix to update the installed version rather than the CLI's self-update commands.
