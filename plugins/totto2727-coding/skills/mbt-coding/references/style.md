# MoonBit Style

> Document type: concrete MoonBit implementation guidance.

## Documentation

Document every public function, type, method, and constant with `///`. State caller-visible behavior and constraints; do not restate the signature.

### Project README

Keep a MoonBit project's canonical README in `README.mbt.md`, and create `README.md` at the project root as a relative symbolic link to `README.mbt.md` so GitHub recognizes and renders the conventional filename while MoonBit can check literate examples.

This matches the default layout generated by [`moon new`](https://docs.moonbitlang.com/en/latest/toolchain/moon/package-manage-tour.html#setup-moonbit-project).

## Names

- Use PascalCase for types and traits.
- Use snake_case for functions, methods, variables, and parameters.
- Preserve standard abbreviations such as JSON and ID; do not invent local abbreviations.
- Name Array values with an `_array` suffix when the suffix prevents ambiguity about the representation.
- Use a bare verb for a mutating operation and a past participle for an immutable operation that returns a new value, such as `sort` versus `sorted`.
- Name the canonical constructor after the type. Name alternate factories by intent, such as `from_corners` or `new_unit`.

## Anonymous functions

Prefer arrow functions for inline callbacks. Use a named local function only when recursion, reuse, or an explicit local signature materially improves the code.

## Labelled arguments

For a top-level function or method with four or more caller-supplied parameters, declare every caller-supplied parameter as labelled (`name~`) or optional labelled (`name?`). Do not keep a positional parameter merely to make a DSL-style call shorter. Keep a method receiver positional and exclude it from the parameter count. This rule does not apply where MoonBit forbids labelled arguments, such as local and anonymous functions, or where an external trait or FFI contract fixes the signature.

## Ignored results

Discard a return value explicitly with `expr |> ignore` when the operation is performed only for its effect.
