## 2. Pulumi ESC

### cloudflare/production

Pulumi Console → **ESC → `cloudflare/production`**: replace `dummy-cloudflare-api-token` with the created token.

## Deployment Access Applications

The production stack defines two self-hosted Access applications, with hostnames configured in `Pulumi.production.yaml`.

| Application   | Protected hostname         | Stack audience output        | Deployment setting                          |
| ------------- | -------------------------- | ---------------------------- | ------------------------------------------- |
| Projektor     | `projektor.totto2727.dev`  | `projektorAccessAudience`    | `wrangler.toml` → `vars.CF_ACCESS_AUDIENCE` |
| Cloudflare OS | `cloudflare.totto2727.dev` | `cloudflareOsAccessAudience` | `deployment.jsonc` → `access.audience`      |

Both applications require the existing AWS SAML identity provider and allow only `kaihatu.totto2727@gmail.com` through the shared deployment-admin policy.
The broader existing SAML policy is not attached to these applications.
Each application protects its entire hostname, uses a 24-hour session, carries the infrastructure ownership tags, and is protected against accidental Pulumi deletion.
Other stacks must explicitly configure `access:projektorDomain` and `access:cloudflareOsDomain` with their own hostnames before deploying.

After reviewing and applying the production stack, read the application-specific AUD values:

```bash
pulumi stack output projektorAccessAudience --cwd infra/cloudflare --stack production
pulumi stack output cloudflareOsAccessAudience --cwd infra/cloudflare --stack production
```

Copy each output into the corresponding deployment repository before running its validation and deployment commands.
The `projektorAccessDomain` and `cloudflareOsAccessDomain` outputs identify which hostname each audience belongs to.
AUD values are generated by Cloudflare, not application IDs, policy IDs, or the Access team domain.
Keep `CF_ACCESS_TEAM_DOMAIN = "totto2727.cloudflareaccess.com"` for Projektor and `access.issuer = "https://totto2727.cloudflareaccess.com"` for Cloudflare OS.
These definitions do not provision Workers, DNS/custom domains, or application storage, which remain owned by the deployment repositories.
If either Access application or an ownership tag already exists outside this stack, import it before applying rather than creating a duplicate.

Projektor's OAuth discovery, token exchange, and MCP routes remain behind Access by default.
No Bypass or Service Auth policy is created automatically.
External OAuth/MCP clients will need a separately reviewed, narrowly scoped authentication design before those workflows can be used.
