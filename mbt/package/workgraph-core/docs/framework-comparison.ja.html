Agent orchestration field guide / 2026-07-31

Workgraph、LangGraph、Google ADK 2.0 機能比較

三者は同じ「エージェントフレームワーク」に見えますが、担当範囲が異なります。この資料では、MoonBit nativeの実行契約、耐久性の高いグラフ実行、総合的なエージェント開発基盤という違いを、列幅を圧縮せず横並びで比較します。

Workgraph

MoonBit向けの型付き実行核

型付きPatch、静的な遷移検証、構造化並行性、Codex/OpenCodeプロセスの安全な所有に集中したWorkgraphモジュール群。

LangGraph

耐久性の高いグラフランタイム

checkpoint、再開、HITL、time travel、並列super-stepを中核に据えた、長時間・ステートフル処理の低レベル基盤。

Google ADK 2.0

エージェント開発の総合SDK

Graph Workflow、Agent、Tool、MCP、A2A、評価、UI、Cloud運用までを一つの体系で扱う広範な開発基盤。

位置付けと実行モデル
主目的 特化

MoonBit native上で決定的なグラフを実行し、LLMやCoding Agentの処理を型付き状態遷移へ統合する。

低レベル基盤

長時間・ステートフルなエージェントやワークフローを、障害から再開可能なグラフとして実行する。

総合SDK

エージェントの構築、ツール連携、協調、評価、可観測性、デプロイまでを一つの開発体系で提供する。

対応ランタイム・言語 MoonBit / native + js core

preferred_target = "native" と supported_targets = "native"。ブラウザやWASM向けランタイムは対象外。

Python / JavaScript

LangGraph SDKとして提供。モデルやTool実装はLangChainまたは独自コードと組み合わせる。

 GraphはPython / Go 2.0

ADK全体はPython、TypeScript、Go、Java、Kotlin。新しいGraph Workflow APIは現時点でPythonとGo 2.0が中心。

グラフ定義 型付き

GraphDefinition[S, P]、Node[S, P]、Reducer[S, P]、Router[S]。状態とPatchを別の型として扱う。

StateGraph

State schema、Reducer、通常Edge、条件付きEdge、Command、Functional APIを提供。

 複数方式

静的なWorkflow graph、Dynamic Workflow、Sequential / Parallel / Loop Agentを用途に応じて選択。

構造検証 厳格

entry、全NodeのRouter、未知の遷移先、到達不能Nodeをcompile時に検出。Routerは取り得る遷移先を事前宣言する。

compileあり

Graphをcompileして実行可能形式にする。条件遷移やCommandにより、実行時の柔軟性を広く確保する。

明示Edge

NodeとEdge、route key、fan-out/fan-inを明示する。複雑な反復や再帰はDynamic Workflowへ移せる。

実行スケジューリング 逐次のみ

1回のiterationで1 Nodeを実行。Cycleは許可され、max_stepsで無限ループを防止する。

並列super-step

複数の遷移先を同じsuper-stepで並列実行。max_concurrencyで並行数を制御できる。

 fan-out / join

Graphのfan-out/join、ParallelAgent、Dynamic Workflowの並列ルートを提供する。
状態、耐久性、Human-in-the-loop
状態モデル 呼び出し内

Nodeが現在状態Sを読み、Patch Pを返す。Reducerだけが状態を更新する。状態はinvoke内のメモリに保持。

Thread / Checkpoint

Graph stateをsuper-stepごとのcheckpointとしてThreadに保存。短期状態と長期Storeを分離できる。

Session / State / Event

Sessionが会話ThreadとEvent履歴を持ち、Stateを保持。Memory ServiceはSessionをまたぐ検索可能な知識を扱う。

永続checkpoint 未実装

pluggable state store、checkpoint serializer、永続run stateはMVP外。

 中核機能

各super-stepのstate snapshotとnode単位のpending writeを保存。Postgres、MongoDB、RedisなどのStore実装を選択可能。

方式依存

Session ServiceとResume機能を提供。Dynamic Workflowは成功済みsub-nodeを記録し、再開時に自動skipする。

障害復旧・再開 run再開なし

Node内のCoding Agent session continuationは扱うが、Graph runそのものを途中checkpointから再開する機能はない。

durable execution

障害後に直前のcheckpointから再開し、同じsuper-stepで成功済みのNodeを再実行せず復旧できる。

 Resume対応

Invocation IDとEvent履歴を使って停止したworkflowを再開。SDK、Agent種別、custom agent実装により対応条件が異なる。

Time travel / Fork 未実装

過去のstate snapshot、replay、別trajectoryへのforkはない。

 標準対応

過去checkpointからのreplayと、状態を編集した分岐runを実行できる。

 Session rewind

Session履歴とResume関連機能はあるが、LangGraphのcheckpoint forkを中心としたtime travelとは設計の焦点が異なる。

Human-in-the-loop 未実装

人間の承認待ちとしてGraph runをsuspendし、後から再開するruntime contractはない。

 interrupt

interrupt()で無期限停止し、stateを確認・変更してCommand(resume=...)で続行できる。

HITL Node

RequestInputやTool confirmationをGraphに組み込み、入力や承認が届くまでworkflowを停止できる。

構成、Agent、Tool連携
Subgraph / Nested workflow 未実装

CompiledGraphを別GraphのNodeとして埋め込む階層化や、親子stateの受け渡し機構はない。

 Subgraph

per-invocation、per-thread、statelessの永続化モードを選択でき、親Graphへの遷移も可能。

 Nested workflow

追加のWorkflow AgentをNodeとして入れ子にし、outputやrouteを外側へ渡せる。
Multi-agent Nodeとして可能

複数のCoding Agent NodeをGraphに置けるが、Supervisor、Team、handoff、subagent固有のruntime abstractionはない。

構築可能

Subgraph、handoff、agent-as-toolを組み合わせる。事前構築済みパターンはLangChainやDeep Agents側が担当。

第一級機能

Coordinatorとsubagent、Chat / Task / Single-turn mode、並列subagent、親Agentへの自動returnを提供。

Remote Agent連携 専用protocolなし

Codex/OpenCode CLI sessionはローカルadapterとして扱う。A2AのAgent Cardやremote discoveryはない。

周辺基盤

LangSmith DeploymentやRemoteGraphではMCP/A2Aを使ったAgent compositionが可能。OSS core単体とは別レイヤー。

A2A

AgentをA2A serverとして公開し、別プロセス・別frameworkのremote agentを利用できる。現状は実験的対応を含む。

LLM・Coding Agent 専用adapter

mizchi/llm callback Node、共通Coding Agent Node、Codex SDK adapter、OpenCode CLI SDK adapterを実装済み。

モデル非依存

LangGraph coreはpromptやmodel architectureを抽象化しない。LangChainまたは独自NodeでLLM/Agentを接続する。

Agent標準搭載

LLM Agent、Managed Agent、Workflow Agent、model routing、複数model providerをSDK体系内で扱う。

Tool・Integration Function境界

任意のasync Function Nodeは実装できるが、Tool registry、schema生成、MCP、OpenAPI、認証統合はない。

周辺ecosystem

任意のPython/JavaScript関数をNodeにできる。豊富なTool統合は主にLangChain側。

 豊富

Function Tool、MCP、OpenAPI、認証、long-running tool、action confirmation、Google Search Groundingなどを提供。

運用、安全性、開発支援
Cancellation・Resource所有 主要な強み

invokeごとのTaskGroup、Node/Run scope session、Node timeout、逆順close、close-once、cancellation-protected cleanupをruntime contractとして持つ。

Node実装依存

Graph runやtaskのcancelは扱えるが、任意のsubprocessや外部resourceの所有・cleanup契約はアプリケーションNode側で設計する。

Run cancellation

RunnerからAgent、Toolへcancelを伝播。ToolはAbortSignal等を使って外部処理の中断を実装できる。

Retry・Cache Agent open retry

Coding Agent session open失敗後の再取得など限定的な回復契約はあるが、汎用Node retry/cache policyはない。

Node policy

NodeごとのRetryPolicyとCachePolicyを指定でき、並列branchの失敗部分だけを再実行できる。

 RetryConfig / Plugin

Node retryのほか、Reflect and Retry Toolsやresponse cacheなどのPluginを利用できる。
Event・Streaming 同期EventSink

Run/Node/Route/Resource lifecycleを同期的・best-effortで通知する。tokenやstate updateを利用者へ流すstream APIはない。

複数stream mode

values、updates、messages、custom、subgraph等をstreamでき、Agent Serverでもリアルタイム配信可能。

Graph制限あり

ADK全体はEventとstreamingを持つが、ADK 2.0のgraph-based workflowは現在live streaming非対応。

Artifact 専用概念なし

coreのnode outputは型付きpatchとoptional JSON valueだけを持つ。成果物が必要な詳細実装はvalueまたはstateへ表現する。

アプリ側設計

state、Store、外部object storageを組み合わせる。ADKのような専用Artifact Serviceはcoreの中心機能ではない。

Artifact Service

session/user scopeのnamed binary data、versioning、InMemory/GCS backendを提供する。
Observability・評価 テスト中心

モジュール別の決定的unit/integration testとローカルCLI process testを持つ。trace UIやagent evaluation frameworkはない。

LangSmithと連携

OSS coreはstream/eventを提供し、trace、Studio、dataset評価、trajectory評価はLangSmithという別製品が担当。

SDK体系内

trajectory/tool-use評価、test/evalset、custom metrics、Trace View、logging、metrics、Plugin callbackを提供。

Deployment ライブラリのみ

API server、worker、control plane、managed deploymentは提供しない。

 LangSmith Deployment

Agent ServerをCloud、Standalone、Self-hostedで運用できる。OSS libraryとmanaged platformは分離されている。

複数経路

ADK API Server、Cloud Run、GKE、Google Cloud Agent Runtime、Agents CLI deploymentを提供。

Decision guide

用途から選ぶ

Choose Workgraph

MoonBitでCoding Agentを安全に動かす

Codex/OpenCodeをNodeとして扱い、subprocessの終了、cancellation、session scope、型付きPatchまで一つのnative runtime契約に収めたい場合。

Choose LangGraph

長時間runを停止・再開・分岐する

障害復旧、checkpoint、HITL、time travel、並列branchが主要要件で、LLMやToolの構成はアプリケーション側で選びたい場合。

Choose Google ADK

Agent製品を一通り構築・運用する

Agent、Tool、MCP、A2A、Memory、Artifact、評価、Web UI、Google Cloud deploymentまで共通SDKの流儀で揃えたい場合。

Workgraph roadmap

他フレームワークへ近づける場合の優先差分

  1. 1. Checkpoint / Resume / HITL

    状態serialization、run ID、checkpoint store、suspend/resume契約を同時に設計する。最も大きい実用上の差。

  2. 2. Fan-out / Join / Subgraph

    bounded parallelism、複数Patchのmerge規則、親子Graphのstate境界を追加する。

  3. 3. Stream / Memory / Artifact Store

    同期EventSinkとは別に利用者向けstream、永続Memory、versioned Artifact backendを定義する。

  4. 4. MCP / A2A / Eval / Deploy

    ここから先はランタイムではなくplatform領域。必要性を確認して個別packageへ分離する。
